01 · THE CORE IDEA

Make a moving system do what you want.

A robot is a physical system. You tell it to move; the world pushes back through friction, delays, noise, imperfect motors, and obstacles. Control theory is the discipline of choosing commands using measurements so the real system still reaches the goal.

Example

Robot follows a path

The robot should follow a figure-eight route. It measures where it is, compares that with the desired point, and changes speed or turning rate.

The difficulty

The model is never perfect

A command of “move at 0.5 m/s” may produce 0.35 m/s because of wheel slip. A useful controller notices the mismatch and reacts.

02 · PLAIN-ENGLISH GLOSSARY

The abbreviations you will see.

State x

The facts that describe the robot now: position, direction, and perhaps velocity. Think: “where am I and how am I moving?”

Control input u

The command we send: for this robot, forward speed and turning speed.

Kinematics

The geometry of motion. It explains how speed and turning change position, without modelling forces in detail.

Feedback

Use the measured outcome to correct the next command. GPS navigation is familiar feedback: it reroutes when you are off course.

LQR

Linear Quadratic Regulator. A mathematically elegant controller for a locally linear model. It balances two wishes: stay near the target, but do not use excessive control effort.

MPC

Model Predictive Control. It predicts several future steps, chooses the best legal sequence of commands, uses only the first command, then repeats with new measurements.

RLS

Recursive Least Squares. A lightweight online learning method. It updates a model estimate continuously as new sensor data arrives.

CBF

Control Barrier Function. A mathematical safety rule. It turns “do not enter this unsafe area” into a constraint for the controller.

03 · HOW A CONTROLLER THINKS

Measure → predict → act → repeat.

1. SenseEstimate position, heading, and speed.
→
2. CompareFind the difference from the desired path.
→
3. DecideCompute a safe speed and turn command.
→
4. MoveThe physical robot responds imperfectly.
→
5. LearnUpdate the model from the new observation.
next state = current state + (model × control command) + disturbance

You do not need to memorise the equation yet. The important idea: the controller predicts what a command will do, then corrects itself when reality differs.

04 · OUR ORIGINAL PROJECT

Adaptive SafeMPC Lab

The project is deliberately more interesting than “make a robot follow a line.” We give the simulated robot an unknown changing motor/wheel gain. For example, a 0.5 m/s command might slowly become 0.35 m/s after wheel slip.

Start with transparent baselines

Compare a simple geometric controller, LQR, and standard MPC under the same path and limits.

Introduce an honest problem

Change the true wheel gain, add sensor noise, and show that the nominal controller is now predicting the wrong motion.

Adapt online

Use RLS to estimate the missing gain from command-and-motion data. Feed that estimate into MPC.

Protect safety

Add an obstacle constraint and later a CBF layer. We will report both successful avoidance and any failures, rather than claiming fake safety.

Already built

Robot model, LQR, a box-constrained MPC baseline, online RLS estimator, automated tests, Modal remote sweep, CI, and a public repository.

Next technical milestone

Simulate fixed and drifting wheel slip, wire the estimator into the predictive model, then run Monte-Carlo comparisons on Modal.

05 · YOUR LEARNING PATH

Learn only what the next step needs.

Week 1: Robot motion

Review coordinate frames, differential-drive kinematics, and why heading matters.

Week 2: Feedback and LQR

Understand tracking error, linearisation, and the trade-off between accuracy and effort.

Week 3: MPC

Learn horizon, cost function, and constraints through the working benchmark.

Week 4: Identification and safety

Study RLS, uncertainty, obstacle constraints, and the limits of a simulated safety claim.

Use the project as a learning laboratory, not as a black box. Every feature should have a small experiment and a written explanation in the LaTeX report.
