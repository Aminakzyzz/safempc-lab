SafeMPC Lab · study plan

Build understanding
before complexity.

A staged roadmap for learning control theory through one reproducible robotics project. Do not advance because a script runs; advance when you can explain the result, reproduce it, and state its limitations.

Operating principle

One question per milestone.

Your output

Evidence, not activity

Every phase ends with a short note, a reproducible experiment, one figure or table, and an explicit limitation.

Avoid

Tool-first learning

Do not start CasADi, ROS 2, or neural methods before you can derive the basic robot model and explain the baseline controller.

Rule: if you cannot explain a result in plain language, it is not finished. Write the explanation in the LaTeX report before moving on.
Six milestones

Roadmap

Phase 0 · orient

Reproduce the current baseline

  • Run the existing simulation and read the controller code without changing it.
  • Draw the robot state: position x,y, heading θ; draw the inputs: forward speed v and turn rate ω.
  • Explain why a command and the actual motion can differ.

Done when: you can explain the simulation loop, the reference path, and every metric in one minute.

Phase 1 · model

Differential-drive kinematics

  • Derive the unicycle kinematic equations.
  • Compare Euler and RK4 integration at two time steps.
  • Show one plot where numerical integration changes the outcome.

Done when: you can state what kinematics omits: forces, tyre dynamics, and actuator dynamics.

Phase 2 · feedback

Tracking with geometric control and LQR

  • Define position error, heading error, and control effort.
  • Run pure pursuit and LQR on the same path and limits.
  • Change LQR weights and explain the accuracy-versus-effort trade-off.

Done when: you can explain LQR as minimising a quadratic cost near a linearised operating point.

Phase 3 · prediction

Constrained MPC

  • Explain horizon, cost, constraints, and receding horizon in your own words.
  • Vary horizon length and input limits; record tracking error and compute time.
  • Compare MPC with LQR fairly using identical conditions.

Done when: you can say why MPC is useful: it handles constraints explicitly, but requires a model and repeated optimisation.

Phase 4 · adaptation

Online system identification

  • Introduce a fixed wheel-speed gain error, then a slowly drifting error.
  • Use RLS to estimate the gain from command and measured speed.
  • Evaluate estimation error, tracking error, and adaptation delay.

Done when: you can explain why “learning” does not automatically mean a neural network.

Phase 5 · safety and evidence

CBF constraints and Monte-Carlo evaluation

  • Read the CBF-QP formulation before implementing it.
  • Separate empirical obstacle avoidance from a formal guarantee.
  • Use Modal for independent trials across noise, delay, drift, and obstacle layouts.

Done when: you can state the assumptions required for the safety claim and report failures honestly.

Beginner resource sequence

Read and watch in this order.

Must watch

  1. MIT 6.832 Lecture 1: Robot dynamics and model-based control. Watch first for the vocabulary and motivation.
  2. MIT OpenCourseWare Underactuated Robotics lectures. Select lectures only when a roadmap phase needs them; do not binge-watch the course.

Must read

  1. Underactuated Robotics: introduction.
  2. MIT notes: LQR.
  3. MIT notes: system identification.
  4. MIT notes: robust control.
  5. python-control tutorial after Phase 2.
  6. CasADi documentation only after Phase 3.

Safety reading for Phase 5

Read Ames et al., Control Barrier Function Based Quadratic Programs for Safety Critical Systems. Read it slowly: identify the safe set, the constraint, and the assumptions before trying to code anything.

Research and documentation routine

Make the report grow with the project.

1

Before coding

Write the experiment question, expected result, assumptions, and metrics in latex/progress.md.

2

After running

Save the seed, parameters, result figure, and one paragraph explaining what happened. Record surprising or negative results.

3

Before the next phase

Add the result to latex/main.tex, cite the source that justifies the method, and state one limitation.

Research quality check: another person should be able to answer: what changed, why it changed, how it was measured, and what the result does not prove.
